Quality upgrades and versions

How MusicHub improves audio quality over time without losing what it had.

What is agreed

Accepted decisions in the logs.

Quality profiles

  • Configurable profiles define acceptable qualities, their preference order, and an upgrade cutoff.
  • Below the cutoff, MusicHub prefers replacing a lower-quality file with a better acceptable version of the same recording when one appears.
  • At the cutoff the track is good enough; higher qualities need not trigger replacement.
  • Quality ranking is configurable; no format or bitrate is hardcoded as universally best.
  • An upgrade preserves the identified recording/version and never silently substitutes a different mix, performance or remaster.

Source log: 2026-10-17-20-30-00-audio-quality-profiles.md

Search priority

  • MusicHub periodically searches for missing wanted tracks and for better versions of tracks below their cutoff.
  • Missing tracks normally get higher priority and/or more frequent searches than upgrades.
  • Intervals and priorities are configurable and need not be uniform; tracks that meet their cutoff need no further upgrade searches.

Source log: 2026-10-17-20-36-00-search-priority-by-availability.md

Album packages and upgrades

  • When a package is acquired, existing tracks are upgraded only if the new file is preferred under the profile and cutoff; otherwise they are retained.

Source log: 2026-10-17-21-00-00-album-package-acquisition-and-per-track-upgrades.md

Identity limits upgrades

  • Better encoding does not outweigh identification confidence: a confident existing recording is not displaced by a less certain candidate.

Source log: 2026-10-17-21-15-00-compare-identification-confidence-of-candidates.md

Superseded versions are kept

  • When a better file becomes preferred, the previous audio file is retained and not automatically deleted.
  • The user can later see an overview of retained versions with their qualities, upgrade history and the current preferred version, and can revert to an earlier file.

Source log: 2026-10-17-21-05-00-retain-superseded-audio-versions.md

Conceptual user journey

An illustrative sequence built from the decisions above; it names no screens, buttons or settings.

  1. A profile says which qualities are acceptable, in what order, and where the cutoff lies.
  2. A track below its cutoff is periodically searched for in better quality, at lower priority than missing music.
  3. When a better file of the same recording is found and passes identity checks, it becomes the preferred version; the old file is kept.
  4. The user can open an overview of versions and upgrade history, and revert if desired.
  5. Once the cutoff is met, upgrade searching for that track stops.

What is not yet decided

  • Quality attributes, default ranking, how profiles are assigned and whether several coexist.
  • Whether replacement is automatic or needs confirmation; comparison of encoding quality and audio integrity.
  • Actual intervals, backoff, and whether settings apply globally, per profile, per track or per task type; effect of search provider rate limits.
  • Retention periods, storage limits and cleanup controls; overview design and fields.
  • How restoring an earlier version interacts with profiles and future upgrade searches.
